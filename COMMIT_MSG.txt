feat: 本地素材标签管理器（打标签 + 按标签浏览 + 标签写进文件名 + 复制导出）

给视频/音频/图片人工打多标签，并把标签直接写进磁盘文件名：
    标签1-标签2-<32位uuid>.<原扩展名>

核心目标是让标签在文件离开本软件后依然可见 —— 拷到 U 盘、手机、电视，
或者直接用资源管理器看，文件名本身就是标签，不依赖任何外挂文件、数据库
或播放器。

调研（见 调研报告.md）的结论：现有方案没有一个把这四件事做全。taggui 最接近，
但标签只存在同名 .txt 里、完全不改素材文件名；FileManagerTag 存 SQLite；
Mp3tag/puddletag 依赖音频容器的可写元数据，视频没有可写的统一标准。

主要功能
- 素材库（源文件夹）可任意指定，从界面选目录或直接粘贴路径，随时可换
- 多标签、批量加/移除标签、标签重命名与合并、标签组合筛选（AND/OR）、
  合集（常用标签组合存起来一键切换）
- 全局唯一：32 位 uuid，目录内不重复；未打标签的素材整理为 未分类-<uuid>.ext，
  「谁还没分类」一眼可见，同时保证 id 始终能从文件名恢复
- 导出 = 复制（原文件不动）：三种命名模式（标签-uuid / 原始文件名含原目录结构 /
  标签-新uuid）、可选 zip、manifest.csv（带 BOM）+ manifest.json、
  SSE 实时进度可取消、导出前体检（缺失源文件/超长路径/被截断的标签）
- 视频缩略图用 ffmpeg 抽帧并缓存，并发上限 2；没有 ffmpeg 时降级为占位图标

安全性设计
- 标签会变成文件名，所以严格校验：禁止 - 和 .（前者是分隔符、后者会破坏扩展名）、
  禁止 Windows 非法字符与保留设备名、上限 40 字符
- 文件名按 UTF-8 字节给 180 预算（中文一字 3 字节），并把完整绝对路径压到
  250 字符以内 —— 因为 Windows 默认 MAX_PATH=260，且不能指望对拷设备开了长路径支持。
  超预算时从末尾丢标签，uuid 与扩展名永不裁剪
- 改名走预写日志（先写日志 → rename → 记账 → 删日志），崩溃后四种状态都能自愈，
  不会出现「库里有记录、磁盘没文件」
- 三层认领防「用户在资源管理器手动改名」：文件名里的 uuid → 文件名反解标签与
  uuid → size:mtimeMs 指纹唯一匹配
- db.json 原子写（tmp + rename）。**损坏时不再回退空库**：那等于把标签悄悄清空，
  现在会把坏文件改名留底（db.json.损坏-xxxxxxxx）并拒绝打开、返回 409 说明原因；
  标签在文件名里有冗余备份，删掉重建即可恢复

实现
- 零依赖：只用 Node 内置模块，不需要 npm install，复制文件夹就能跑
- 服务只绑 127.0.0.1，默认端口 8787，内置 HTTP 服务含完整 Range 支持
- 目录选择用 PowerShell 调 Win32 FolderBrowserDialog，失败时回退页面内目录浏览器
- 双击入口 start.cmd 的名称与内容都用纯 ASCII：中文 Windows 的默认代码页是 936，
  带非 ASCII 的批处理实测会被 cmd 解析出错（详见 验证报告.md 4.14）

验证（见 验证报告.md）
- 4 套自验证共 340 项全绿（`npm run verify:all`）：
  verify.js 201 / browser_test.js 40（真 Chrome 走完整交互）/
  e2e_real.js 83（用真实 738MB 视频）/ probe_external.js 16（外部改名容错）
- 真素材实测：593MB 视频改名 3ms（fs.rename 不搬数据）、738MB 导出逐字节一致、
  ffmpeg 抽帧确认是可解码 JPEG（480×854）
- 过程中发现并修掉 14 个产品 bug（路由把 res 传成捕获组字符串导致一批接口 500、
  批量加标签不传 mode 会把已有标签清空、重复导出静默覆盖上次成果、
  db.json 损坏被静默换成空库、启动遮罩被 CSS display 盖过 hidden、
  启动脚本被中文文件名与 LF 行尾搞坏等）
  与 4 个测试自身的 bug（含一条「看起来在测其实被跳过」的 ffmpeg 检查，
  以及「损坏时回退空库」这条把 bug 写成断言的检查）
